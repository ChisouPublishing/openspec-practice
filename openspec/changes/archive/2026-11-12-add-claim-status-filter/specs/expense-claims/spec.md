# Spec Delta

## ADDED Requirements

### Requirement: 一覧の状態による絞り込み
システムは `GET /expense-claims` にクエリ `status` が指定されたとき、「申請の一覧」で返す対象の申請のうち、状態がその値と一致するものだけをステータス 200 で返さなければならない（SHALL）。並び順と各申請の項目は「申請の一覧」と同じとする。`status` が指定されない場合は、状態に関わらず返さなければならない（SHALL）。出し直された元の申請は状態が `rejected` のまま扱う。

#### Scenario: 承認者が未判断の申請だけを見る
- **WHEN** 申請者 `u1` と `u2` の申請がそれぞれ未判断・承認済み・差戻しの状態である中で、承認者が `status=pending` で一覧を取得する
- **THEN** ステータス 200 が返り、`u1` と `u2` の未判断の申請だけが新しい順で返る

#### Scenario: 申請者は自分の申請の中から絞り込む
- **WHEN** 申請者 `u1` と `u2` がそれぞれ未判断の申請と承認済みの申請を持つ状態で、`u1` が `status=approved` で一覧を取得する
- **THEN** ステータス 200 が返り、`u1` の承認済みの申請だけが返る

#### Scenario: 差戻しで絞り込むと出し直された元の申請も含まれる
- **WHEN** 差戻された申請が出し直されて新しい申請が未判断である状態で、承認者が `status=rejected` で一覧を取得する
- **THEN** ステータス 200 が返り、元の申請が含まれ、出し直した申請は含まれない

#### Scenario: 該当する申請がない
- **WHEN** 承認済みの申請が 1 件もない状態で、承認者が `status=approved` で一覧を取得する
- **THEN** ステータス 200 と空配列が返る

#### Scenario: 指定しない場合はすべての状態を返す
- **WHEN** 未判断・承認済み・差戻しの申請がある状態で、承認者が `status` を付けずに一覧を取得する
- **THEN** ステータス 200 が返り、3 件すべてが返る

### Requirement: 絞り込む状態の検証
システムは一覧 API の呼び出し時にクエリ `status` を検証し、不正な場合は一覧を返さずにステータス 400 を返さなければならない（SHALL）。`status` は `pending`・`approved`・`rejected` のいずれか 1 つでなければならない（MUST）。空文字・大文字小文字の違う値・複数の指定は不正とする。利用者の識別（401）は、この検証より先に行わなければならない（SHALL）。

#### Scenario: 存在しない状態
- **WHEN** 承認者が `status=draft` で一覧を取得する
- **THEN** ステータス 400 が返る

#### Scenario: 空の値
- **WHEN** 承認者が `status=` で一覧を取得する
- **THEN** ステータス 400 が返る

#### Scenario: 大文字で指定する
- **WHEN** 承認者が `status=PENDING` で一覧を取得する
- **THEN** ステータス 400 が返る

#### Scenario: 複数の状態を指定する
- **WHEN** 承認者が `status=pending&status=rejected` または `status=pending,rejected` で一覧を取得する
- **THEN** ステータス 400 が返る

#### Scenario: ヘッダーがなく状態も不正
- **WHEN** `X-User-Id` を付けずに `status=draft` で一覧を取得する
- **THEN** ステータス 401 が返る（400 ではない）
