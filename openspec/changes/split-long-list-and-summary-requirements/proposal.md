## Why

`allow-withdraw-pending-claim` をアーカイブした後、`openspec validate --all --strict` が失敗するようになった。確定した仕様 `expense-claims` の「申請の一覧」と「月ごとの集計」の要件の本文が 500 文字を超え、strict では警告も失敗として扱われるためである。機能を足すたびに例外の扱いを 1 つの要件に書き足してきた結果であり、このままでは次の変更も検証を通せない。

## What Changes

- 「申請の一覧」を削除し、同じ内容を 2 つの要件に分けて追加する。
  - 「申請の一覧の対象と並び順」：返す対象（申請者は自分の申請、承認者はすべて）と並び順（作成日時の新しい順）。
  - 「一覧の申請の項目」：各申請が含む項目と、どの場合にどの項目が `null` になるか。
- 「月ごとの集計」を削除し、同じ内容を 2 つの要件に分けて追加する。
  - 「月ごとの集計の対象と応答」：集計の対象（経費の日付 `date` が指定した月に含まれる、すべての申請者の申請）と応答の形（`month`、`byStatus` の 4 つのキー、`0` の扱い）。
  - 「集計での取り下げと出し直しの扱い」：取り下げた申請は `withdrawn` にだけ数えること、出し直した申請と元の申請を別々に数えること。
- 既存のシナリオは文言を変えずに、分けた先の要件へ移す。
- 「一覧の状態による絞り込み」の本文は「申請の一覧」を参照しているため、参照先を「申請の一覧の対象と並び順」（対象・並び順）と「一覧の申請の項目」（項目）に直す。
- API の振る舞いは変えない。**BREAKING** な変更はない。

元の要件名を残したまま分ける方法（MODIFIED でシナリオを減らす、同じ名前で REMOVED と ADDED を書く）は、どちらも OpenSpec の検証で拒否されるため、分けた先の要件には新しい名前を付ける。

## Capabilities

### New Capabilities

（なし）

### Modified Capabilities

- `expense-claims`：「申請の一覧」「月ごとの集計」を削除して 4 つの要件に分け直し、「一覧の状態による絞り込み」の参照先を直す。要件の分け方と名前が変わるだけで、求める振る舞いは変わらない。

## Impact

- 仕様：`openspec/specs/expense-claims/spec.md`（アーカイブ時に反映される）。
- コード：`src/` は変更しない。
- テスト：`test/expense-claims.api.test.js` の `describe` は要件名ごとにまとまっているため、要件名の変更に合わせてグループ名とテストの置き場所を直す。テストの中身（呼び出しと確認）は変えない。
- API・データベース・依存パッケージ：変更なし。

## 対象外

- 要件の振る舞いの変更（項目の追加・削除、`null` の規則、集計の数え方の変更など）。
- シナリオの追加・削除・文言の書き換え（移動だけを行う）。
- 500 文字を超えていない他の要件の整理や分割。
- `openspec validate` の文字数の基準を変える、または strict をやめること。
- `src/` のコードと、テストの呼び出し・確認の内容の変更。
